# 技术债与风险

## 当前缺口

- 需求边界已确认，首版 PRD 已确认但尚未进入实现；UI 资产和具体验收证据仍待建立。
- 尚未选择桌面框架、语言、系统音频捕获方案和本地文件格式。
- 尚未建立服务端代理、火山引擎 STT 接入、鉴权、超时和错误映射。
- 尚未建立安装/运行、测试、Lint、构建和 CI 配置。

## 主要风险

- 系统播放音频捕获与麦克风捕获是不同能力，不能混为一谈。
- 服务端代理虽允许短暂接收音频，但不得保存音频、文本、缓存或可还原日志。
- 火山引擎 STT 和代理网络会引入费用、网络和服务可用性问题。
- 长录音需要明确磁盘空间、崩溃恢复和中断处理策略。
- 删除录音与 Markdown 必须处理部分成功，避免用户误以为两者均已删除。
- “尽可能快”不是量化指标，测试应记录实际处理时延但不以固定时延作为本期验收门槛。

## 建议顺序

1. 完成 UI 设计与关键状态确认。
2. 验证 Windows 系统音频捕获和火山引擎 STT 代理链路。
3. 依据验证结果选择技术栈并建立最小测试与构建基础。
4. 用户明确授权后进入首个功能的开发 Loop。
